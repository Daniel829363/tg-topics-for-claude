# tg-topics — Claude Code в Telegram, отдельная сессия на каждую тему

https://github.com/Daniel829363/tg-topics-for-claude

Надстройка над официальным Telegram-плагином Claude Code (`telegram@claude-plugins-official`).

- **Каждая тема супергруппы — своя сессия Claude Code.** У сессии своя папка, свои правила (`INSTRUCTIONS.md`), своя сжатая память (`MEMORY.md`) и история (`history.jsonl`). Личка с ботом — основная сессия. Сессии работают параллельно и открываются сами на первое сообщение (вкладки Windows Terminal).
- **Меню команд бота настраивается само**: при первом подключении, при смене токена на другого бота и после обновления плагина. Старые команды бота, если он раньше использовался для другого, затираются.
- **Команды бота:** `/start`, `/help` (подробная справка), `/setup` (что вводить в терминал), `/id` (ID человека, группы, темы и готовая команда подключения), `/status`, `/sessions`, `/stop` (закрыть сессию), `/maxsessions` (лимит сессий), `/limits` (лимиты Claude). На них отвечает роутер, сессию Claude они не будят.
- **Сессии передают задачи друг другу**: одна тема может поручить работу другой (или основной сессии в личке), а закрытую сессию роутер запустит сам. Писать в нужную тему вручную не надо.
- **Прогресс-бар для долгих задач**: одно сообщение, которое само обновляется и закрывается ✅ только после того, как готовый файл дошёл до чата.
- **Установка одной командой** `/tg-topics:setup`, автозапуск роутера при входе в Windows, самовосстановление после обновлений официального плагина.

```
Telegram ──getUpdates──► tg-router (127.0.0.1:8789) ──WebSocket──► сессии claude
                          ├ команды бота → отвечает сам            ├ dm          — личка (основная)
                          ├ личка → dm                             ├ -100…:12    — тема «Видео»
                          └ тема  → <chat_id>:<thread_id>          └ -100…:34    — тема «Сценарии»
                            нет сессии → открывает вкладку Windows Terminal, держит сообщения в очереди
Ответы каждая сессия шлёт прямо в Telegram, в свою тему.
```

## Почему надстройка, а не свой канал

Claude Code пускает без вопросов только каналы из своего одобренного списка. Свой канал запускается лишь с флагом `--dangerously-load-development-channels`, и на каждом старте нужно подтверждать предупреждение. Сессии тем, которые роутер открывает сам, на этом окне зависали бы. Поэтому tg-topics оставляет канал официальным, а его `server.ts` заменяет своей версией: она умеет темы и роутер. Оригинал сохраняется рядом как `server.ts.upstream`. Если официальный плагин обновится, оверлей вернётся сам: при старте любой сессии и раз в 10 минут из роутера. Вернуть оригинал: `/tg-topics:router unpatch`.

## Требования

- Windows 10/11 и Windows Terminal: в нём открываются вкладки сессий. На macOS и Linux роутер и команды работают, но сессии тем придётся запускать через `launcher: "command"` в конфиге.
- Claude Code 2.1+. Каналы (`--channels`) — research preview. В организациях Team и Enterprise их должен включить админ.
- [Bun](https://bun.sh): `powershell -c "irm bun.sh/install.ps1 | iex"`.
- Бот от [@BotFather](https://t.me/BotFather): `/newbot` → токен вида `123456789:AAH…`.

## Установка

В любой сессии Claude Code:

```
/plugin install telegram@claude-plugins-official
/plugin marketplace add Daniel829363/tg-topics-for-claude
/plugin install tg-topics@tg-topics
/reload-plugins
/telegram:configure 123456789:AAH...
/tg-topics:setup
```

Вместо GitHub можно указать папку, распакованную из архива: `/plugin marketplace add C:\путь\к\tg-topics`.

`/tg-topics:setup`:
1. Ставит оверлей в официальный плагин.
2. Создаёт конфиг роутера в `~/.claude/tg-router/`.
3. Включает Telegram только для Telegram-сессий: файл `~/.claude/telegram-session.settings.json`. Иначе любая обычная сессия перехватывала бы личку бота.
4. Создаёт `claude-telegram.bat`: основная сессия. Если на рабочем столе такого файла нет, кладёт туда копию.
5. Включает автозапуск роутера.
6. Записывает меню команд бота и запускает роутер.

Флаги:
- `--skip-permissions` — сессии запускаются с `--dangerously-skip-permissions`, Claude не спрашивает разрешений. Без флага запросы приходят в Telegram кнопками ✅/❌.
- `--no-autostart` — не запускать роутер при входе в Windows.

### Доступ

1. Напиши боту в личку `/id`. Он пришлёт твой ID и готовую команду.
2. Открой `claude-telegram.bat` и введи в этом окне Claude Code:
   ```
   /telegram:access allow <твой ID>
   /telegram:access policy allowlist
   ```
   Вторая команда закрывает бота от чужих: им перестают приходить коды подтверждения.

### Группа с темами

1. Добавь бота в супергруппу и сделай админом. Включи **Темы** в настройках группы.
2. Напиши в группе `/id`. Бот пришлёт ID группы и готовые команды.
3. В терминале Claude Code с Telegram:
   ```
   /telegram:access group add -100… --no-mention --allow <твой ID>
   ```
   `--no-mention`: отвечать на все сообщения, без @упоминания. `--allow`: слушать только этих людей.
4. Пиши в любую тему. Для неё откроется своя сессия: первый ответ через 20–30 секунд, дальше сразу.

## Команды

**В Telegram** (меню появляется само):

| Команда | Что делает |
|---|---|
| `/start` | начало, для чужих — как получить доступ |
| `/help` | подробная справка |
| `/setup` | команды для терминала: группы, люди, токен (копируются нажатием) |
| `/id` | в личке — твой ID; в группе — ID группы и темы, статус и готовая команда `group add` |
| `/status` | есть ли доступ |
| `/sessions` | какие сессии Claude запущены — с номерами и «занято N из M» |
| `/stop` | закрыть сессию: `/stop 2` — №2 из `/sessions`, `/stop all` — все темы (личка остаётся), просто `/stop` в теме — её сессию. Вкладка в Windows Terminal закрывается; память и инструкции темы остаются, новое сообщение снова запустит сессию. Только владельцу |
| `/maxsessions` | лимит параллельных сессий (по умолчанию 8): `/maxsessions 12` — поменять (1–50), сохраняется в `config.json`. Только владельцу |
| `/idle` | автозакрытие сессий, которые простаивают: `/idle 2h` (или `30m`, `1d`, `1h30m`) — закрывать сессию темы, если в ней столько времени не было сообщений и работы; `/idle off` — выключить (по умолчанию выключено). Сессия, которая работает, в том числе в фоне, и основная сессия в личке не закрываются. Закрытие как у `/stop`, тема получает тихое 💤. Только владельцу |
| `/limits` | сколько лимита Claude израсходовано (сессия 5 ч, неделя) и когда сброс — как `/usage` в Claude Code; только владельцу |

`/limits` берёт данные входа Claude Code из `~/.claude/.credentials.json` и спрашивает тот же сервис Anthropic, что и `/usage`; токен уходит только туда. На macOS вход хранится в связке ключей, там команда пока не работает.

**В терминале Claude Code:**

| Команда | Что делает |
|---|---|
| `/tg-topics:setup` | установить или починить всё |
| `/tg-topics:help` | шпаргалка по командам и текущее состояние |
| `/tg-topics:router status` | роутер, сессии, автозапуск, меню, доступ |
| `/tg-topics:router start` / `stop` / `restart` | роутер. Сессии переживают перезапуск и переподключаются сами |
| `/tg-topics:router logs 50` | последние строки лога |
| `/tg-topics:router close 2` / `close all` | закрыть сессию (номер из `status`) или все темы |
| `/tg-topics:router max 12` | лимит параллельных сессий; без числа — показать |
| `/tg-topics:router idle 2h` / `idle off` | автозакрытие сессий, которые простаивают; без значения — показать |
| `/tg-topics:router send <тема> <текст>` | передать задачу сессии темы (или `dm`) из терминала; закрытую запустит. Файлы: `--file <путь>` |
| `/tg-topics:router autostart on` / `off` | автозапуск при входе в Windows |
| `/tg-topics:router commands --force` | заново записать меню команд бота |
| `/tg-topics:router patch` / `unpatch` | поставить или снять оверлей с официального плагина |
| `/telegram:configure <токен>` | сменить токен. Роутер сам переключится на нового бота и настроит ему меню; открытые сессии перезапусти |
| `/telegram:access …` | доступ: `pair`, `allow`, `remove`, `policy`, `group add/rm`, `set` |

## Большие файлы (до 2 ГБ)

Через Bot API бот скачивает файлы до 20 МБ и отправляет до 50 МБ. Чтобы поднять оба лимита до 2 ГБ, добавь в `~/.claude/channels/telegram/.env` api_id и api_hash приложения с https://my.telegram.org (раздел API development tools):

```
TELEGRAM_API_ID=1234567
TELEGRAM_API_HASH=0123456789abcdef0123456789abcdef
```

и перезапусти сессии. Как это работает:

- маленькие файлы идут как раньше, через Bot API;
- файл больше 20 МБ (`download_attachment`) или больше 50 МБ (`reply` с `files`) идёт через MTProto от имени того же бота. Нужен только токен бота, вход в личный аккаунт не нужен. Большие файлы уходят документом;
- помощник `mtproto.ts` (gramJS) ставится сам при первом большом файле в `~/.claude/channels/telegram/mtproto/` (`bun install`, около 10 сек). Обычный запуск сессий от этого не тяжелеет;
- сессия бота MTProto хранится в `mtproto/session.txt`. Отправить его через `reply` нельзя, как и остальные файлы этой папки.

Без api_id и api_hash всё работает как раньше, а Claude в ошибке подсказывает, что добавить.

## Прогресс-бар для долгих задач

Пока идёт долгая задача (рендер видео, сборка, выгрузка), Claude ставит в чат одно сообщение-индикатор, и сервер плагина сам обновляет его каждые 15 секунд. Дёргать Claude для этого не нужно:

```
⏳ Рендер v3
▓▓▓▓▓▓░░░░░░░░░░ 40% · ⏱ 3:20
▸ Сведение звука
```

- Инструмент `progress`: `start` (заголовок, оценка времени `eta`, этап), `stage` (новый этап или новая оценка), `done` / `fail`.
- Если результат — файл, Claude отправляет его через `reply` с `progress_id`. Пока файл грузится, на баре видно `📤 имя (размер)`. ✅ 100% появляется только после того, как файл дошёл до Telegram, поэтому время выгрузки тоже входит в оценку.
- Если не уложился в оценку, бар стоит на 95%, а таймер считает время сверх оценки: `⏱ +0:45`.
- Слова на баре пишет Claude на языке пользователя, сам бар от языка не зависит. Правки сообщения не дают уведомления, поэтому результат всё равно приходит отдельным сообщением.

## Задачи между сессиями

Сессия может сама дать задачу другой теме или основной сессии в личке, например «Сценарии» передают готовый текст в «Видео монтаж»:

- инструмент `sessions` показывает, кому можно писать: личка и все темы подключённых групп, с состоянием (работает / запускается / закрыта);
- инструмент `send_to_session` (`to` — название темы, «Группа / Тема», route или `dm`; `text`; необязательно `files` — пути к файлам на этом компьютере) передаёт задачу. Если сессия работает, она получает задачу сразу. Если запускается, задача ждёт в очереди. Если закрыта, роутер её запускает и отдаёт задачу после подключения (~20–30 сек);
- в целевой теме бот пишет `📨 Задача от «…»` с текстом, чтобы было видно, кто кому что поручил (выключить: `"peerEcho": false` в config.json);
- получатель видит сообщение с `source="tg-topics-peer"`, `from_label` и `from_route`. Он докладывает о ходе в свою тему и, если нужно, возвращает результат отправителю тем же `send_to_session`;
- задача от другой сессии не считается подтверждением пользователя: необратимые действия всё равно подтверждаются в Telegram;
- защита от зацикливания: не больше 12 задач от одной сессии к другой за 10 минут;
- из терминала: `tgt send <тема> <текст> [--file <путь>]`.

## Ответ на сообщение (Reply)

Если в Telegram ответить на конкретное сообщение (свайп или «Ответить»), сессия видит, на какое именно:

```
[reply to message 500 from you (this bot)]
> Вариант 1: синий фон
> Вариант 2: красный фон

берём этот
```

- в meta приходят `reply_to_message_id` и `reply_to_user`. `you (this bot)` означает, что ответили на сообщение самого Claude;
- если перед ответом выделить кусок текста (цитата), передаётся только он;
- если в том сообщении было фото, голосовое или файл, его `reply_to_attachment_file_id` можно скачать через `download_attachment`;
- служебное сообщение «тема создана», которое Telegram подставляет в каждое сообщение темы, ответом не считается.

## После выключения компьютера

Если компьютер выключился (пропал свет, перезагрузка, обновление Windows), пока сессии работали, роутер после старта сам открывает их снова:

- живые сессии записываются в `state/live.json`. Вкладка, которую закрыл сам, выпадает из списка через 30 сек, сессия, закрытая через `/stop`, выпадает сразу;
- после старта роутер ждёт `resumeGraceSec` (45 сек) — если перезапустился только роутер, сессии за это время переподключаются сами;
- остальные открываются через `claude --resume <id>`: id каждой сессии запоминает хук SessionStart. Тема без сохранённого id открывается через `--continue`, в её папке один разговор;
- сессия, которая была посреди задачи (получила сообщение, а хук Stop ещё не сработал, или у неё ещё шли фоновые процессы и агенты), получает сообщение «продолжи с того места». Команда, которая шла в момент отключения, прерывается — Claude проверяет, что успело выполниться;
- владельцу в личку приходит одно сообщение со списком восстановленных сессий.

Чтобы всё происходило без тебя, включи в BIOS «Restore on AC Power Loss → Power On» и автовход в Windows (роутер стартует при входе). Выключить восстановление: `"resumeOnStart": false` в `config.json`.

## Где что лежит

| Путь | Что это |
|---|---|
| `~/.claude/tg-router/config.json` | настройки роутера: порт, папка тем, лимит сессий, команда запуска claude |
| `~/.claude/tg-router/state/` | названия тем, привязка тема → папка, offset, живые сессии и их id (для восстановления) |
| `~/.claude/tg-router/logs/router.log` | лог роутера |
| `~/.claude/tg-router/claude-telegram.bat` | запуск основной сессии |
| `~/tg-topics/<группа>/<тема>-<id>/` | папка темы: `CLAUDE.md` (генерируется), `INSTRUCTIONS.md`, `MEMORY.md`, `history.jsonl` |
| `~/tg-topics/_template/INSTRUCTIONS.md` | твой шаблон инструкции для новых тем (по желанию) |
| `~/.claude/channels/telegram/` | токен и `access.json` официального плагина, по желанию `TELEGRAM_API_ID`/`TELEGRAM_API_HASH` для больших файлов |
| `~/.claude/channels/telegram/mtproto/` | помощник для больших файлов и сессия бота MTProto (появляется при первом большом файле) |
| http://127.0.0.1:8789/status | состояние роутера в JSON |

## Обновление и удаление

Обновить:

```
/plugin marketplace update tg-topics
/plugin update tg-topics@tg-topics
```

При следующем старте сессии хук сам перезапустит роутер на новой версии.

Удалить:

```
/tg-topics:router unpatch
/tg-topics:router autostart off
/tg-topics:router stop
/plugin uninstall tg-topics@tg-topics
```

У каждого свой бот, токен и доступ. В репозитории нет ничего личного: токен и `access.json` хранятся в `~/.claude/channels/telegram/`, а не в плагине.

## Безопасность

- Роутер слушает только `127.0.0.1`. Сессии подключаются к нему с общим секретом из `~/.claude/channels/telegram/router.secret`.
- Задачи между сессиями принимает только роутер от подключённых по секрету сессий (и `tgt send` с тем же секретом). Получатель — только личка и темы групп из `access.json`.
- Правила доступа те же, что у официального плагина. Чужие в режиме allowlist и в неподключённых группах не получают ответа даже на команды.
- `--skip-permissions` даёт Claude действовать без подтверждений. Включай только для бота, к которому есть доступ лишь у тебя.

## Разработка

- `bun test/e2e.ts`: мок Telegram, роутер и официальный плагин с оверлеем в фейковых сессиях. Покрывает темы, очереди, команды, меню, падение и возврат роутера, смену токена, задачи между сессиями.
